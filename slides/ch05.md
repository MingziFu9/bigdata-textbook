# 5.1 Hive 解决什么问题

## 用 SQL 查 HDFS 上的大数据
- 把 HDFS 上的文件“看成”一张表
- 表结构单独记录：列名、类型、目录
- 写 **HiveQL**，Hive 翻译成分布式计算
- 数据不搬家，会 SQL 就能分析
::: notes
Facebook 2008 年前后为分析师开发，后来捐给 Apache。
:::

## 数据库和数据仓库
| 比较项 | 数据库（MySQL） | 数据仓库（Hive） |
|---|---|---|
| 用途 | 支撑业务：下单、付款 | 支撑分析：报表、统计 |
| 操作 | 增删改单条，毫秒级 | 扫描上亿行，几秒到几分钟 |
| 数据 | 当前业务数据 | 多个系统、几年的历史 |
::: notes
一句话：数据库管“做生意”，数据仓库管“看生意”。企业两者都用，每天夜里同步。
:::

# 5.2 数据仓库入门

## 四层：ODS → DWD → DWS → ADS
| 层 | 放什么 | 小象优选 |
|---|---|---|
| ODS | 原样同步来的数据 | `ods_orders` |
| DWD | 清洗后的明细 | `dwd_order_detail` |
| DWS | 按常用维度汇总 | `dws_province_day` |
| ADS | 直接给报表用 | `ads_province_daily_report` |
::: notes
做菜比方：原材料 → 净菜 → 半成品 → 端上桌的菜。分层让清洗好的数据被很多报表共用、口径一致。
:::

## 事实表和维度表
- **事实表**：发生过的业务事件，带可累加的数字
- **维度表**：描述事件的角度：谁、什么、在哪
- 套路：事实表关联维度表，按维度分组汇总
- 例：订单 JOIN 商品，按品类求销售额
::: notes
记住这个套路，大部分报表 SQL 都写得出来。
:::

# 5.3 看懂背后发生了什么

## 一张表 = 表结构 + HDFS 文件
!mermaid 1
- **Metastore**：存表结构
- HDFS：存数据文件
- **HiveServer2**：接 SQL，交给 **Tez** 计算
::: notes
Hive 本身不存数据也不计算，是个“翻译”。往表目录放同格式文件，再查就能查到。
:::

| 容器 | 作用 | 端口 |
|---|---|---|
| metastore | 表结构存在 Derby | 9083 |

::: notes
命令要带 -f docker-compose.yml -f docker-compose.hive.yml。第一次启动约 1 分钟。不需要 worker3。

# 5.4 建表与导入

## 常用数据类型
| 类型 | 例子 |
|---|---|
| `STRING` | 订单号、省份 |
| `INT` / `BIGINT` | 数量 / 订单总数 |
| `DECIMAL(10,2)` | 金额（别用 DOUBLE） |
| `DATE` / `TIMESTAMP` | 注册日期 / 下单时间 |

## 内部表和外部表
| 比较项 | 内部表 | 外部表 |
|---|---|---|
| 建表 | `CREATE TABLE` | `CREATE EXTERNAL TABLE ... LOCATION` |
| DROP 时 | 结构和数据一起删 | 只删结构，**文件还在** |
| 适合 | 加工出的中间表、结果表 | ODS 原始数据 |
::: notes
实验 5-1 第 5 步亲手验证。Hive 4 中不带事务的 CREATE TABLE 显示为外部表，但 DROP 仍删数据。
:::

## 分区表
![HDFS 上 orders_part 的 dt= 子目录](img/hive_partitions.png)
- 按日期分开存，每天一个 `dt=` 子目录
- 条件有分区字段 → 只读需要的目录（**分区裁剪**）
- 按最常用的查询条件分区，不要太细
::: notes
按“日期 + 用户”分区会产生几百万个小目录，回到小文件问题。分区字段是“虚拟列”，来自目录名。
:::

## 实测：分区快多少
| 查询 | 读了多少行 | 耗时 |
|---|---|---|
| 不分区，查一天 | 3,000,000 | 约 7.2 秒 |
| 分区表，查一天 | 99,888 | 约 1.0 秒 |
| 分区表，查整月 | 约 300 万 | 约 3.7 秒 |
::: notes
实验 5-2，300 万行订单。只读约 3% 的数据。
:::

- 选“某一天”：只有一个格子变蓝

- 只按省份筛选：分区帮不上忙

## 把数据导入表
| 办法 | 写法 |
|---|---|
| 外部表指向目录 | `CREATE EXTERNAL TABLE ... LOCATION` |
| 装载文件 | `LOAD DATA INPATH '...' INTO TABLE t;`（移动文件） |
| 查询结果写入 | `INSERT OVERWRITE TABLE t SELECT ...` |
| 动态分区 | `SET hive.exec.dynamic.partition.mode=nonstrict;` |
::: notes
动态分区写 300 万行约 34 秒，自动建 30 个分区。加工后的表用 ORC：10 万行 CSV 约 8 MB，DWD 的 ORC 约 1.1 MB。
:::

# 5.5 常用查询

## 分组统计和多表连接
```sql
SELECT p.category, SUM(o.amount) AS gmv
FROM ods_orders o JOIN ods_products p ON o.product_id = p.product_id
WHERE o.status = '已完成'
GROUP BY p.category ORDER BY gmv DESC;
```
::: notes
结果：手机数码 97860811.40 元居首，订单不到两成、销售额七成多；图书文具 469955.50 元最少。LEFT JOIN 保留左表全部行。
:::

## 排序取前几名
- `ORDER BY ... LIMIT 10`：排行榜
- ORDER BY 全部汇总到一个 Reducer，务必加 LIMIT
- `SORT BY` 只在每个 Reducer 内排序，别用错

## 窗口函数：排名、累计、环比
| 用途 | 写法 |
|---|---|
| 排名 | `RANK() OVER (PARTITION BY dt ORDER BY gmv DESC)` |
| 累计 | `SUM(gmv) OVER (PARTITION BY province ORDER BY dt)` |
| 环比 | `LAG(gmv) OVER (PARTITION BY province ORDER BY dt)` |
::: notes
PARTITION BY 是计算范围，和分区表的“分区”是两回事。实验 5-3 日报：9 月 30 日广东第一，山东环比 +37.4%，四川 −31.3%。第 8 章还会系统练。
:::

# 5.6 数据从哪来，什么时候不该用 Hive

## 用 DataX 每天同步数据
- 业务数据在 MySQL，每天要进 ODS
- **DataX**：读插件 + 写插件，JSON 配置
- 写成 ODS 表的一个分区目录，再 ADD PARTITION
- 调度系统每天凌晨自动跑
::: notes
阿里巴巴开源，国内最常用。本书不要求动手搭。
:::

## 什么时候不该用 Hive
| 场合 | 更好的选择 |
|---|---|
| 几万、几十万行 | MySQL 或 pandas |
| 查单个用户、毫秒返回 | MySQL |
| 大屏一两秒出结果 | Doris、StarRocks |
| 复杂清洗、机器学习 | Spark（第 6～10 章） |

## 前沿视窗：更快的查询引擎
- MPP 架构：各节点同时算，秒级返回
- **Doris**（百度开源）、**StarRocks**：国产开源
- 常见组合：Hive/Spark 夜间加工 → ADS 导入 Doris 供大屏
- 建表、分区、分层、窗口函数都相通

## 实验常见问题
- 少了一张表：分号后同一行写了注释

## 本章小结
- Hive 表 = **Metastore** 表结构 + HDFS 文件
- 数据仓库四层：ODS、DWD、DWS、ADS
- 外部表删表不删数据；分区表只读需要的分区
- 分组统计、多表连接、TopN、窗口函数
- 数据由 DataX 同步进 ODS；交互式查询用 Doris 等
