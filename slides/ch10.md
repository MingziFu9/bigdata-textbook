# 10.1 机器学习速记

## 机器学习在做什么
| 类型 | 有没有标签 | 本章的例子 | 常用模型 |
|---|---|---|---|
| 分类 | 有，标签是类别 | 下周会不会复购 | 逻辑回归、随机森林 |
| 回归 | 有，标签是数值 | 下个月卖多少 | 线性回归 |
| 聚类 | 没有 | 用户分成三四群 | K-Means |
- **特征**：描述样本的列（次数、金额、等级）
- **标签**：要预测的结果
::: notes
以前是人把规则写死，机器学习是把历史数据交给算法，让它自己找规律，找到的规律叫模型。
:::

## 训练集、测试集和过拟合
```python
train, test = data.randomSplit([0.8, 0.2], seed=10)   # seed 固定，每次分得一样
```
- 考试不能考原题：训练集学，测试集考
- **过拟合**：训练集上很好，测试集上明显变差
- 模型越复杂越容易过拟合

## 什么时候用 Spark 做机器学习
| 比较项 | scikit-learn | Spark MLlib |
|---|---|---|
| 数据放在哪里 | 一台电脑的内存 | 集群各节点 |
| 数据量 | 几百万行以内 | 上亿行 |
| 小数据上的速度 | 快 | 慢（有调度开销） |
| 适合 | 数据小或已抽样 | 单机放不下，或数据本来在集群上 |
::: notes
原则同第 8 章“pandas 还是 Spark”。本章给 spark 容器加装了 NumPy（labs/cluster/spark/Dockerfile），MLlib 需要它。
:::

# 10.3 MLlib 的固定套路

## 六个步骤
!mermaid 1
- ① 按用户汇总，一个用户一行
- ② 特征处理 → ③ 组装特征向量
- ④ 选模型 → ⑤ 串成 Pipeline
- ⑥ 评估、保存
::: notes
不管做分类还是聚类，都是这个套路。第 ① 步就是前几章的 DataFrame 操作。
:::

## 特征处理的四个组件
| 组件 | 作用 | 例子 |
|---|---|---|
| `StringIndexer` | 文字类别编号 | 普通 → 0、白银 → 1…… |
| `OneHotEncoder` | **独热编码** | 黄金（2）→ [0, 0, 1] |
| `VectorAssembler` | 组装**特征向量** | R、F、M、等级 → features |
| `StandardScaler` | **标准化** | 金额和次数缩放到同一量级 |
::: notes
为什么独热：编号后模型会以为钻石（3）是白银（1）的 3 倍。为什么标准化：金额几千、次数几次，不缩放的话系数没法比、K-Means 被金额一个特征说了算。
:::

## Pipeline：把步骤串起来
```python
pipeline = Pipeline(stages=[indexer, encoder, assembler, scaler, lr])
model = pipeline.fit(train)        # 训练：每一步学出自己的参数
pred = model.transform(test)       # 预测：按训练时的方式处理新数据
```
- **fit**：从数据中学（Estimator）
- **transform**：用学好的东西加新列（Transformer）
- 训练和使用走同一条流水线，不会出错
::: notes
StringIndexer 学的是哪个等级编几号，StandardScaler 学的是标准差，LogisticRegression 学的是系数。
:::

# 10.4 常用的三个模型

## 逻辑回归：算出“是”的概率
| 列 | 内容 | 例子 |
|---|---|---|
| `rawPrediction` | 原始分数 | `[1.11, -1.11]` |
| `probability` | 每一类的概率 | `[0.7517, 0.2483]` |
| `prediction` | 预测的类别 | `0.0` |
- 概率大于 0.5 预测为“是”
- 好解释：购买次数 F 的系数 +1.217，影响最大
::: notes
逻辑回归名字里有“回归”，却是最常用的分类模型。系数正的说明特征越大越可能复购。
:::

## 随机森林：很多棵树一起投票
```python
from pyspark.ml.classification import RandomForestClassifier
rf = RandomForestClassifier(featuresCol="features", labelCol="label", numTrees=50, maxDepth=5)
pipeline = Pipeline(stages=[indexer, encoder, assembler, scaler, rf])
```
- 只换最后一步，前面不用改
- 能给出特征重要性
- 实验 10-1：AUC 0.638，只比逻辑回归高 0.007
::: notes
瓶颈在特征，不在模型。
:::

## K-Means 聚类
!sim dist-kmeans
- 选 k 个中心 → 每个点归最近的中心 → 重算中心
- Spark 上：Driver 广播中心，各节点本地求和
- 网络上只传“人数和坐标之和”
::: notes
选 k = 3，按“下一步”看一轮里的三个步骤，验证坐标之和 ÷ 人数 = 新中心；再换几组初始中心看结果会不会变。
:::

## 用 K-Means 分群的两件事
- **标准化**：否则金额一个特征决定分群
- **取对数**：次数最多的用户买了 386 次，长尾要压短
- **轮廓系数**：−1～1，越大分得越清楚
- k 最终结合业务定：运营管得过来的三五群
::: notes
实验 10-2：k=2 轮廓系数 0.504 最高，k=4～6 约 0.45，簇内距离平方和一直下降没有拐点。只分 2 群太粗，选 k=4。
:::

## 实验 10-2：四群画像
| 起名 | 人数占比 | 画像 | 销售额占比 |
|---|---|---|---|
| 忠实大客户 | 12.6% | 6 天前买过，5.5 次，9603 元 | 41.5% |
| 近期活跃客户 | 32.8% | 7 天前，1.6 次，3269 元 | 36.8% |
| 沉睡客户 | 28.5% | 23 天没来，1.2 次，2107 元 | 20.6% |
| 小额尝鲜客 | 26.1% | 1.1 次，121 元 | 1.1% |
::: notes
营销建议：忠实大客户重点维护；近期活跃推荐关联商品；沉睡客户发唤回券；小额尝鲜客低门槛满减、控制成本。与 RFM 八类大方向一致。
:::

# 10.5 评估、调参和保存

## 准确率的陷阱
| | 预测不复购 | 预测复购 |
|---|---|---|
| **真实不复购** | 6525 | 65 |
| **真实复购** | 1538 | 203 |
- 准确率 80.8%，全说“不复购”也有 79%
- 1741 个复购用户只找出 203 个
- 正负样本差得多时，不能只看准确率
::: notes
大部分用户只买过一两次，复购概率都在 0.16～0.25，很少超过 0.5 的阈值。这张表就是混淆矩阵。
:::

## AUC：看排序能力
- 随机抽一个复购、一个不复购的，模型给复购的打分更高的可能性
- 0.5 = 抛硬币，1 = 完全排对，和阈值无关
- 实验 10-1：**AUC 0.631**
- 按概率挑前 20%：命中 38.5%，是随便挑的 **1.8 倍**
::: notes
营销中模型的用法往往不是判断是或不是，而是排个队，先给最有希望的人发券。AUC 不高是因为随书数据的性别、年龄、等级都是随机的；真实业务加入浏览、加购等行为特征，AUC 一般能到 0.7～0.8。
:::

## 保存模型和批量打分
```python
best.write().overwrite().save("file:///labs/data/models/repurchase")
model = PipelineModel.load("file:///labs/data/models/repurchase")
scored = model.transform(all_users)
```
- **批量打分**：每天凌晨给全部用户算分数
- 铁律：新数据的特征和训练时算法完全一样
- 实验 10-3：48644 个老用户，前 20% 共 9740 人
::: notes
营销名单中忠实大客户 5942 人、近期活跃 3446 人。特征用同一个 features.py 计算，避免口径不一致。
:::
