# 7.1 数据清洗做什么

## 脏数据长什么样
| 问题 | 例子 | 不处理会怎样 |
|---|---|---|
| 重复值 | 同一订单出现两次 | 订单数、销售额偏大 |
| 缺失值 | 省份、金额为空 | 多出“空”省份，销售额偏小 |
| 格式不一 | 广东 / 广东省；前后空格 | 分组被拆散 |
| 类型错误 | `¥233.8`；4 种时间写法 | 无法求和、按日期统计 |
| 异常值 | 数量为 0、金额为负 | 统计结果被拉偏 |

## 数据质量看哪几个方面
| 方面 | 小象优选的例子 |
|---|---|
| 规范性 | 时间统一为 `yyyy-MM-dd HH:mm:ss` |
| 完整性 | 省份、金额、支付方式不为空 |
| 准确性 | 金额 = 单价 × 数量，不能为负 |
| 一致性 | 订单表与用户表的省份一致 |
::: notes
国标 GB/T 36344—2018 共六个方面，另两个是时效性和可访问性。清洗主要解决前四个。
:::

# 7.2 DataFrame 入门

## DataFrame：带列名和类型的表
| 比较项 | RDD | DataFrame |
|---|---|---|
| 数据 | 任意 Python 对象 | 有列名、有类型的行 |
| 写法 | lambda 函数 | 列名 + 现成函数，或 SQL |
| 优化 | 按原样执行 | 自动选择更快的方式 |
- 入口：**SparkSession**，pyspark 里叫 `spark`

## 读入数据
| 格式 | 写法 |
|---|---|
| CSV | `spark.read.csv(路径, header=True, inferSchema=True)` |
| 文本 | `spark.read.text(路径)`，只有一列 `value` |
| Parquet | `spark.read.parquet(路径)` |
- `printSchema()` 看每列的名字和类型
- **读脏数据时先不推断类型**，全部当字符串
::: notes
只要有一个 ¥233.8，整列金额就只能推断成字符串。
:::

## 查看、选列、过滤、新增列
| 操作 | DataFrame 写法 | SQL |
|---|---|---|
| 看前几行 | `df.show(5)` | `LIMIT 5` |
| 选列 | `df.select("order_id", "amount")` | `SELECT` |
| 过滤 | `df.filter(F.col("amount") > 5000)` | `WHERE` |
| 新增列 | `df.withColumn("unit", ...)` | `AS unit` |
| 分组 | `df.groupBy("province").count()` | `GROUP BY` |
::: notes
多个条件用 &、|、~，每个条件加括号。DataFrame 也是惰性的；withColumn 返回新 DataFrame，要写 df = df.withColumn(...)。describe() 看最小、最大值。
:::

# 7.3 常用清洗操作

## 去重
| 写法 | 什么算重复 |
|---|---|
| `df.dropDuplicates()` | 所有列都相同 |
| `df.dropDuplicates(["order_id"])` | 订单号相同 |
- 脏订单 102000 行，整行重复 2000 行
- 统一格式后**再按订单号去重一次**
::: notes
统一格式前，“广东”和“广东省”两行看起来不一样，去重去不掉。
:::

## 缺失值：删、填还是补
| 办法 | 写法 | 实验 7-1 的规则 |
|---|---|---|
| 删除 | `df.dropna(subset=[...])` | — |
| 填固定值 | `df.fillna({"pay_type": "未知"})` | 支付方式 |
| 按规则补 | `F.coalesce(列1, 列2)` | 金额 = 单价 × 数量；省份查用户表 |
::: notes
直接 dropna() 剩 100681 行，删掉的 1319 行里有 1300 个真实订单，销售额跟着没了。
:::

## 类型转换：cast 和 try_cast
- Spark 4 默认 **ANSI 模式**：转不了就报错
- `cast("decimal(10,2)")` 遇到 `¥59.80` → `CAST_INVALID_INPUT`
- 先去 ¥，再 `try_cast`：失败返回 NULL
- 转换后**再统计一次空值**，多出来的就是丢了的
::: notes
金额用 decimal 不用 double，避免 0.1 + 0.2 = 0.30000000000000004。顺序反了，800 个带 ¥ 的金额都变成空值。
:::

## 字符串处理
| 函数 | 作用 |
|---|---|
| `F.trim` | 去前后空格：8 种支付方式写法合并成 4 种 |
| `F.lower` | 用户编号统一小写 |
| `F.regexp_replace` | 替换：去 ¥、去省份后缀 |
| `F.regexp_extract` | 取出某一部分 |
| `.rlike` | 判断是否符合模式 |

## 正则表达式
| 符号 | 意思 |
|---|---|
| `\d`、`\S` | 一个数字、一个非空白字符 |
| `+`、`{n}` | 重复 1 次以上、正好 n 次 |
| `^`、`$` | 开头、结尾 |
| `( )` | 分组，按组号取出 |
```python
F.regexp_replace(F.trim("province"), "(省|市|壮族自治区|...|自治区)$", "")
```
::: notes
$ 不能省。省份从 63 种写法变成 31 种，正好 31 个省级行政区。
:::

## 日期解析：4 种写法
| 例子 | 解析格式 |
|---|---|
| `2026-09-05 07:08:36` | `yyyy-MM-dd HH:mm:ss` |
| `2026/9/9 17:17:09` | `yyyy/M/d HH:mm:ss` |
| `2026-09-05T23:37:51` | `yyyy-MM-dd'T'HH:mm:ss` |
| `20260914 193753` | `yyyyMMdd HHmmss` |
- 每种用 `try_to_timestamp` 试一遍，`coalesce` 取第一个成功的
::: notes
解析后仍为空的是 0 行。不为 0 就 show 出来，看漏了什么写法。
:::

## 异常值
- **按业务规则**：数量 > 0、金额 > 0、时间在 9 月内
- **按统计规律**：`describe()` 看最小、最大值
- 实验 7-1 三类各 100 行，删掉
- 金额为 NULL 时 `amount <= 0` 也是 NULL，`filter` 会悄悄删掉
- 所以**先补缺失值，再删异常值**

# 7.4 多表合并

## 用左连接补充信息
| 连接方式 | 结果 |
|---|---|
| `"inner"`（默认） | 只留两边都匹配上的 |
| `"left"` | 保留左表全部行，匹配不上为 NULL |
| `"left_anti"` | 只留左表中匹配不上的 |
- 订单一个都不能少 → **左连接**
- 合成 16 列的**宽表**；先统一格式再合并
::: notes
U0090022 不先转小写就关联不上用户表。合并后检查没关联上的行数，实验 7-3 中是 0。
:::

# 7.5 保存清洗结果

## Parquet：列式存储
!mermaid 2
- 只读用到的列
- 压缩更小：日志 70.2 MB → 19.1 MB
- 自带列名和类型
::: notes
第 5 章 Hive 的 ORC 也是列式存储，思路相同。
:::

## 按日期分区写出
```python
clean.write.mode("overwrite").partitionBy("dt") \
     .parquet("file:///labs/data/xiaoxiang_clean/orders")
```
- `overwrite`：目录存在就覆盖
- 每天一个 `dt=2026-09-01` 子目录，查几天只读几天
::: notes
和第 5 章分区裁剪是一回事。
:::

## 实验常见问题
- `CAST_INVALID_INPUT`：先去掉 ¥，再用 `try_cast`
- 行数比 99700 少：先删异常值、后补缺失值了
- `\d` 不起作用：正则字符串要加 `r` 前缀
- 宽表行数变多：维度表里编号不唯一
- `PATH_ALREADY_EXISTS`：写出时加 `mode("overwrite")`

## 本章小结
- 先看数据、定规则，再清洗、核对、记录
- DataFrame：带列名和类型，读脏数据先全当字符串
- 去重、补缺失、`try_cast`、正则、日期解析、删异常值
- 顺序很重要：统一格式在合并前，补缺失在删异常前
- 左连接合成宽表，按日期分区存 Parquet
