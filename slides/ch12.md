# 12.1 选对图表

## 先想清楚要说明什么
| 想说明什么 | 推荐的图 | 小象优选的例子 |
|---|---|---|
| 比较 | 柱状图、条形图 | 各品类销售额 |
| 趋势 | 折线图 | 每日销售额 |
| 构成 | 饼图、环形图 | 支付方式占比 |
| 分布 | 直方图 | 订单金额 |
| 关系 | 散点图 | 订单数与销售额 |
| 转化 | **漏斗图** | 浏览 → 加购 → 下单 → 支付 |
::: notes
口诀：比较用柱，趋势用线，构成用饼，分布用直方，关系用散点，地区用地图，转化用漏斗。
:::

## 好图表的共同点
- 标题写结论：“手机数码占了近七成销售额”
- 交代单位、数据范围、数据来源
- 一张图只说一件事
- 去掉 3D、阴影、花哨背景
- 漏斗：浏览 93474 人 → 支付 2592 人（2.8%）
::: notes
流失最多的是“浏览 → 加购”这一步（只剩 31.1%），运营应该先在商品详情页上下功夫。
:::

## 当心误导性图表
- 柱状图纵轴不从 0 开始：多 15% 看起来高 10 倍
- 气泡按半径画：1.6 倍变成 2.5 倍
- 饼图类别太多：31 个扇形读不出来
- 两个单位不同的量硬放一个纵轴
- 只截取对自己有利的时间段
::: notes
折线图靠起伏表达变化，纵轴可以不从 0 开始，但要写明起点。参考《统计数字会撒谎》（1954）。
:::

# 12.2 用 pyecharts 画图

## ECharts 与 pyecharts
- ECharts：国产开源图表库，捐给 Apache
- **pyecharts**：用 Python 生成 ECharts 网页
- 可交互：鼠标看数值、点图例、地图缩放
- 分工：Spark 把大数据算小，pyecharts 画小结果
::: notes
实验 12-1：Spark 从 10 万行宽表算出 5 张小表（8、30、31、5、4 行），pyecharts 在本机画图。
:::

## 三步画一个图
```python
bar = (
    Bar()                                                  # ① 创建
    .add_xaxis(["手机数码", "家用电器", "服饰鞋包"])          # ② 加数据
    .add_yaxis("销售额（万元）", [9759.7, 2200.3, 1044.1])
    .set_global_opts(title_opts=opts.TitleOpts(title="各品类销售额"))   # ③ 选项
)
bar.render("bar.html")
```
::: notes
换图只要换类名：Line、Pie（radius 设成环形）、Funnel、Map。常用选项：LabelOpts、MarkPointOpts、MarkLineOpts、AxisOpts(min_=300)、VisualMapOpts。
:::

# 12.3 用 Superset 搭数据看板

## 从报告到看板
- **商业智能**（BI）工具：不写代码做图表
- **数据看板**：几个指标和图表放一页，刷新即更新
- **Superset**：Apache 开源 BI，本书用 6.1.0
- 国产：DataEase（开源）、FineBI、Quick BI
::: notes
pyecharts 报告适合每月一次的固定报告；看板适合业务人员随时自己看、自己筛选。
:::

## Superset 的四个概念
!mermaid 1
- 数据库：SQLAlchemy URI
- 数据集：选一张表
- 图表：指标、维度、过滤条件
- 看板：拼起来、排版
::: notes
Superset 把图表翻译成 SQL 交给数据库执行，不负责计算大数据。所以看板背后应该是 Spark 算好的结果表。
:::

# 12.4 大数据项目的数据合规

## 两部法律
| | 个人信息保护法 | 数据安全法 |
|---|---|---|
| 施行 | 2021 年 11 月 1 日 | 2021 年 9 月 1 日 |
| 保护 | 个人的权益 | 数据安全、国家安全和公共利益 |
| 要点 | 合法、正当、必要；敏感信息单独同意；去标识化等措施 | 分类分级保护；安全管理制度；事件报告 |

## 必须分清的概念
- **个人信息**：与已识别或可识别的自然人有关
- **敏感个人信息**：身份证号、银行卡、行踪、医疗……
- **去标识化**：不借助额外信息认不出，仍是个人信息
- **匿名化**：认不出且不能复原，不再是个人信息
::: notes
条文：个人信息保护法第四条、第二十八条、第七十三条。各省销售额这样的汇总结果是匿名的。
:::

## 数据分类分级
- 数据安全法第二十一条；GB/T 43697—2024 先分类、再分为核心、重要、一般三级
| 小象优选的数据 | 内部级别 | 措施 |
|---|---|---|
| 身份证号、手机号 | 高 | 脱敏存储，审批后才能看原文 |
| 订单明细 | 中 | 分析时只用用户编号 |
| 销售汇总 | 低 | 内部共享 |
::: notes
GB/T 43697—2024 于 2024 年 3 月 15 日发布、10 月 1 日实施。企业日常处理的大多是一般数据，内部还可以再细分级别。
:::

## 数据脱敏的常用写法
| 方法 | 例子（虚构数据） |
|---|---|
| 遮盖 | `100****9113`、`992703********5612`、`谢*` |
| 截断 | `河南郑州****` |
| 泛化 | 37 岁 → 30～39 岁 |
| 加盐哈希 | `sha2(身份证号 + 盐, 256)` |
| 汇总 | 各省销售额 |

## 脱敏的代码
```python
F.concat(F.substring("phone", 1, 3), F.lit("****"), F.substring("phone", 8, 4))
F.concat(F.substring("id_card", 1, 6), F.lit("********"), F.substring("id_card", 15, 4))
F.regexp_replace("address", r"[^\x00-\x7F]{2}[路街]\d+号$", "****")
F.sha2(F.concat("id_card", F.lit(SALT)), 256)
```
- 脱敏后一定要检查：完整手机号 0 个、完整身份证号 0 个
::: notes
为什么加盐：身份证号格式固定，不加盐可以穷举反查。盐要像密码一样保管。加盐哈希属于去标识化，结果仍是个人信息。
:::

# 12.5 综合项目

## 七步流水线
!mermaid 2
- 采集 → 脱敏 → 清洗 → 统计 → 分群 → 入库 → 看板
- `lab12_3_pipeline.sh` 一次跑完，编者实测 204 秒
- 真实公司交给 Airflow、DolphinScheduler 每天调度
::: notes
其中清洗最长，约 90 秒。
:::

## 项目报告与评分
| 评分项 | 分值 |
|---|---|
| 流程完整、能运行 | 30 |
| 数据处理与合规 | 20 |
| 分析结论与可视化 | 20 |
| 报告质量 | 15 |
| 答辩 | 15 |
- 报告七部分：背景、数据、方案、处理、结果、问题、分工
::: notes
3～4 人一组，10 分钟答辩。可以扩展：换 Parquet 比较速度、加实时大屏、加复购预测指标。
:::

## 前沿视窗：智能 BI
- 用自然语言问数据，自动出 SQL 和图表
- 口径要先定义：退款算不算销售额？
- 重要数字要能看到背后的 SQL
- 数据不能随意发给外部服务；问数也要守权限
::: notes
工具越来越智能，但提出好问题、判断结果对不对、合法合规地用数据，仍然要靠人。
:::
