## 情景导入：一块硬盘坏了
- 三个月的日志存在一块硬盘上，没有备份
- 硬盘坏了，季度报表做不出来
- 问题一：日志越来越多，一台装不下
- 问题二：几百块硬盘，天天有坏的
::: notes
这两个问题谷歌 2003 年就遇到了，答案是 GFS；Hadoop 照着实现了 HDFS。
:::

# 3.1 HDFS 解决什么问题

## 一块“超级硬盘”
- 很多台机器的硬盘拼成一个文件系统
- **拆开存**：大文件切块分散到多台机器
- **多存几份**：每块存几份副本，坏一台不丢
- 用 `/xiaoxiang/logs/access.log` 这样的路径访问
::: notes
装不下就加机器，硬盘坏了数据还在。
:::

## 设计取舍
- 机器坏是常态，靠软件容错
- 为**大文件**设计，怕大量小文件
- **一次写入、多次读取**，只能追加不能改中间
- 重吞吐、轻延迟，查单条记录用数据库
::: notes
这几条决定了什么数据适合放 HDFS，3.5 节会再总结。
:::

# 3.2 看懂背后发生了什么

## NameNode 和 DataNode
- **NameNode**：记账，元数据放在内存里
- **DataNode**：存数据块，每台工作节点一个
- 图书馆比方：总目录台 vs 书架
- **心跳**每 3 秒一次，**块报告**定期发送
::: notes
借书的人先问目录台，再自己去书架取书，目录台不经手书本身。
:::

## 数据块与副本
- 块默认 **128 MB**，最后一块按实际大小存
- 副本默认 3 份，随书集群 2 份
- 同一块的副本一定放在**不同机器**
- 多机架：第 1 份本机，第 2 份另一机架，第 3 份同第 2 份机架
::: notes
块大，读写时间主要花在传输上；NameNode 要记的块也少。第 4 章：一个块一个 Map 任务。
:::

## 算一算
| 文件 | 块数 | 占用空间 |
|---|---|---|
| 1 GB，副本 3 | 1024 ÷ 128 = 8 块 | 3 GB |
| 701.8 MB 大日志，副本 2 | 6 块，最后一块约 61.8 MB | 约 1.4 GB |
::: notes
副本数 N：同时坏 N−1 台不丢数据；坏 N 台可能丢（正好是同一块所在的 N 台）。
:::

## 读写一个文件
- **写**：问 NameNode 放哪 → 数据流水线传给几台 DataNode
- **读**：问 NameNode 在哪 → 直接从 DataNode 读
- 数据**不经过** NameNode
- 刚启动处于**安全模式**，只读不写
::: notes
流水线：worker1 一边存一边转给 worker2，客户端只传一遍。
:::

## 机器坏了怎么办
- 读到坏机器：客户端自动改读别的副本
- 很久没心跳：判定死亡（默认 10 分 30 秒，随书约 1.5 分钟）
- 自动复制，补齐**副本不足**的块
- 机器回来：删掉多余副本
::: notes
实验 3-2 实测：停掉 worker2，87 秒后判定死亡，十几秒内补齐到 worker3。
:::

# 3.3 常用操作

## hdfs dfs 常用命令
| 类别 | 命令 |
|---|---|
| 目录 | `-ls -h` `-mkdir -p` `-count` |
| 上传下载 | `-put -f` `-get` |
| 查看 | `-cat` `-head` `-tail` |
| 整理 | `-cp` `-mv` `-rm -r` |
| 空间与副本 | `-du -h` `-df -h` `-setrep` |
::: notes
-put/-get 一边是本地路径一边是 HDFS 路径。HDFS 相对路径指 /user/用户名，本书一律写完整路径。
:::

# 3.4 用 Python 读写 HDFS

## WebHDFS 与 HttpFS
- WebHDFS：HTTP 接口，`/webhdfs/v1/路径?op=操作`
- 直接访问 NameNode：读文件会跳到 `worker1:9864`，本机访问不到
- **HttpFS**（14000 端口）：由 master 代为转发
- Python 用 `requests` 就能读写
::: notes
另一种办法是 pyarrow 直连，速度快但要装 Java 和 Hadoop 客户端，配置复杂。
:::

## 常用操作一行代码
| 操作 | op |
|---|---|
| 列目录 | `LISTSTATUS` |
| 读文件 | `OPEN` |
| 建目录 | `MKDIRS` |
| 写文件 | `CREATE`（`overwrite=true`） |
| 删除 | `DELETE` |
::: notes
读到字节交给 pd.read_csv(io.BytesIO(...))；写时 df.to_csv(index=False).encode("utf-8")。适合几百 MB 以内的文件，更大交给 Spark。
:::

# 3.5 使用注意

## 小文件问题
- 每个文件、目录、块约占 NameNode **150 字节**内存
- 1 个 1 GB 文件：约 1.35 KB
- 100 万个 1 KB 文件：约 **300 MB**
- 存之前先把小文件合并成大文件
::: notes
同样 1 GB 数据，NameNode 负担差 20 多万倍。小文件多了，MapReduce 的 Map 任务也多，计算慢。
:::

## HDFS 和对象存储怎么选
| 对比 | HDFS | OSS、OBS 等 |
|---|---|---|
| 维护 | 自己运维 | 云服务商负责 |
| 扩容 | 加机器 | 不用管 |
| 价格 | 一次性投入 | 按用量付费 |
| 性能 | 数据就在本机，读得快 | 走网络 |
::: notes
自建集群用 HDFS，上云优先考虑对象存储。Hadoop、Spark 都能直接读写 oss://、obs:// 路径。
:::

## 前沿视窗：存算分离
- 数据放对象存储，计算集群按需开关
- 华为云 MRS 支持对象存储作集群存储
- 阿里云 OSS-HDFS：兼容 HDFS 接口，程序改路径就能用
- 切块、副本、元数据分离的思想都相通
::: notes
hdfs dfs -ls oss://bucket.endpoint/dir/ 这样的命令照样能用。
:::
