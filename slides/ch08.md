# 8.1 两种写法：DataFrame 与 SQL

## Spark SQL：两种写法，一个引擎
| 比较项 | DataFrame 函数 | SQL 语句 |
|---|---|---|
| 写起来 | 可以拆步、加变量和循环 | 一条完整语句 |
| 适合 | 步骤多、和 Python 结合 | 一次性统计、从 Hive 迁移 |
- SQL 前先注册**临时视图**：`done.createOrReplaceTempView("orders")`
- `spark.sql(...)` 返回的也是 DataFrame
::: notes
两种写法交给同一个优化器，速度一样。实际工作常混用。
:::

## 同一个问题两种写法
```python
# DataFrame 写法
done.groupBy("category").agg(F.sum("amount").alias("gmv"),
    F.countDistinct("user_id").alias("buyers")).orderBy(F.desc("gmv"))
# SQL 写法
spark.sql("""SELECT category, SUM(amount) AS gmv, COUNT(DISTINCT user_id) AS buyers
             FROM orders GROUP BY category ORDER BY gmv DESC""")
```
::: notes
两种写法结果完全相同：手机数码 97597310.90 元居首，客单价 6620.81 元；图书文具最少。
:::

## SQL 与 DataFrame 对照
| SQL | DataFrame |
|---|---|
| `WHERE 条件` | `.filter(条件)` |
| `GROUP BY a` + 聚合 | `.groupBy("a").agg(...)` |
| `HAVING` | `.agg(...)` 后再 `.filter` |
| `ORDER BY a DESC` | `.orderBy(F.desc("a"))` |
| `LIMIT 10` | `.limit(10)` |
| `JOIN ... ON` | `.join(另一个, "列名", "left")` |

# 8.2 常用分析

## 分组聚合
| 函数 | 注意 |
|---|---|
| `F.sum`、`F.avg`、`F.max` | 空值不参与计算 |
| `F.count("*")` | 行数 |
| `F.count("列")` | 该列不为空的行数 |
| `F.countDistinct("列")` | 数下单用户必须用它 |
- 两个维度：`groupBy("province", "category")`
- TopN：`orderBy(F.desc("gmv")).limit(10)`

## 透视表
```python
done.groupBy("level").pivot("category").agg(F.round(F.sum("amount") / 10000, 1))
```
- 行是会员等级，列是品类，和 Excel 数据透视表一样
- 各等级都是手机数码买得最多
- 只对取值不多的列透视
::: notes
普通会员手机数码 5384.5 万元，钻石会员 468.3 万元。不要对用户编号这类列透视。
:::

# 8.3 窗口函数

## 保留每一行，多算一列
| 部分 | SQL | DataFrame |
|---|---|---|
| 分组 | `PARTITION BY province` | `Window.partitionBy("province")` |
| 排序 | `ORDER BY gmv DESC` | `.orderBy(F.desc("gmv"))` |
| 范围 | `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW` | `.rowsBetween(-6, 0)` |
::: notes
和 GROUP BY 的区别：GROUP BY 把一组合成一行，窗口函数保留每一行。要先 from pyspark.sql import Window。
:::

## 分组排名：每省前 3 品类
```python
w = Window.partitionBy("province").orderBy(F.desc("gmv"))
top3 = by_pc.withColumn("rank", F.row_number().over(w)).filter("rank <= 3")
```
| 店铺 | 销售额 | row_number | rank | dense_rank |
|---|---|---|---|---|
| A | 300 | 1 | 1 | 1 |
| B | 200 | 2 | 2 | 2 |
| C | 200 | 3 | 2 | 2 |
| D | 100 | 4 | 4 | 3 |
::: notes
广东、浙江都是手机数码、家用电器、服饰鞋包。每组只取 3 个用 row_number；并列都要列出用 rank 或 dense_rank。
:::

## 累计、移动平均、环比
| 计算 | 写法 |
|---|---|
| 累计 | `F.sum("gmv").over(w.rowsBetween(Window.unboundedPreceding, 0))` |
| 7 日移动平均 | `F.avg("gmv").over(w.rowsBetween(-6, 0))` |
| 环比 | `F.lag("gmv", 1).over(w)`，（本期 − 上期）÷ 上期 |
::: notes
9 月 1 日没有上一行，环比是 NULL；前 6 天移动平均凑不满 7 天。9 月 25 日环比 −10.6%。不分组的窗口会警告 No Partition Defined，30 行没问题，上亿行要先聚合。
:::

# 8.4 常用指标与用户分层

## 指标先说清口径
| 指标 | 算法 | 9 月结果 |
|---|---|---|
| **GMV** | 已完成订单金额之和 | 141,636,638.80 元 |
| **客单价** | 销售额 ÷ 下单用户数 | 2,911.70 元 |
| 笔单价 | 销售额 ÷ 订单数 | 1,580.06 元 |
| **复购率** | 买 2 次及以上的用户 ÷ 下单用户 | 37.7% |
::: notes
订单 89640 笔，下单用户 48644 人，复购 18358 人。同一个名字不同公司口径可能不同，报告要注明。
:::

## 转化率与留存率
- **转化率** = 下单用户 ÷ 访问用户
- 9 月 30 日：访问 99046 人，下单 3078 人，3.11%
- **留存率**：之前的用户之后还活跃的比例
- 第一周 16323 人，第二周又下单的 4156 人，周留存 25.5%
::: notes
转化率用访问日志和订单 join 求既访问又下单的用户。
:::

## RFM：用三个数给用户分层
| 指标 | 含义 | 越……越好 |
|---|---|---|
| R | 最近一次购买距今几天 | 越小越好 |
| F | 购买次数 | 越大越好 |
| M | 购买金额 | 越大越好 |
- 每项与平均值比，分出高低（R 13.0 天、F 1.84 次、M 2911.70 元）
- 高低组合成 8 类用户

## RFM 分层结果
| 用户类型 | 人数 | 销售额占比 | 运营建议 |
|---|---|---|---|
| 重要价值（高高高） | 6911 | 50.9% | 重点维护 |
| 重要挽留（低低高） | 3117 | 13.9% | 大额券召回 |
| 重要发展（高低高） | 2424 | 11.0% | 推荐配件 |
| 重要唤回（低高高） | 1778 | 9.3% | 短信、推送唤回 |
| 一般挽留（低低低） | 14031 | 4.6% | 低成本触达 |
::: notes
14% 的重要价值用户贡献一半销售额。一万张券优先给重要挽留和重要唤回（合计 4895 人）。F 最大值 386，可能是企业采购，分层前先看极端值。
:::

# 8.5 连接 Hive 与 MySQL

## 读写 Hive 表
- 建 SparkSession 时加 `enableHiveSupport()`
- `spark.table("xiaoxiang.ods_orders")` 读
- `saveAsTable("xiaoxiang.ads_category_daily")` 写
- 坑：Spark 不认 `skip.header.line.count`，表头被当成一行
::: notes
100001 行，多的一行就是表头，用 filter 去掉。Spark 通过 Metastore 知道表结构和位置，自己读 HDFS，不经过 Tez。
:::

## 用 JDBC 写进 MySQL
```python
url = "jdbc:mysql://mysql:3306/xiaoxiang"
props = {"user": "root", "password": "xiaoxiang",
         "driver": "com.mysql.cj.jdbc.Driver"}
daily.write.mode("overwrite").jdbc(url, "category_daily", properties=props)
```
- 驱动 jar 用 `--jars /labs/jars/mysql-connector-j-8.4.0.jar`
- 容器里写 `mysql:3306`，本机写 `localhost:3306`
::: notes
240 行写入 MySQL，与第 5 章 Hive 的品类总额一致。overwrite 会删表重建，需要索引就先建表再 append。
:::

# 8.6 pandas 和 Spark 怎么选

## 实测：同一个统计
| 数据量 | pandas | pandas 内存 | Spark |
|---|---|---|---|
| 1 万行 | 0.02 秒 | 4.6 MB | 3.9 秒 |
| 10 万行 | 0.19 秒 | 45.5 MB | 1.1 秒 |
| 100 万行 | 2.2 秒 | 455 MB | 2.0 秒 |
| 300 万行 | 6.4 秒 | 1366 MB | 2.5 秒 |
::: notes
Spark 不含启动的约 3 秒；spark-submit 整个程序约 15 秒。按比例 3000 万行 pandas 要 13 GB 内存。
:::

## 怎么选
| 情况 | 选择 |
|---|---|
| 几百万行以内，探索、画图 | pandas |
| 几千万行以上，或在 HDFS、Hive 上 | Spark |
| 每天定时运行、越来越多 | Spark |
| 大数据算出的小结果 | pandas 画图、做报告 |

## 实验常见问题
- `TABLE_OR_VIEW_NOT_FOUND`：没注册临时视图
- 下单用户数比订单数大：用了 `count` 而不是 `countDistinct`
- R、F、M 变成“高”“低”：列名不区分大小写，新列被覆盖
- `ClassNotFoundException`：JDBC 驱动没下载或路径错
- 读 Hive 表多 1 行：表头被当成数据
