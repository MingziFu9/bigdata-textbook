# 2.2 Docker 够用就好

## 为什么用 Docker
- 把软件和整个运行环境**打包**，到哪都一样
- 像集装箱：整箱搬走，到哪打开都一样
- 比虚拟机省资源，一台笔记本能跑好几个
- 弄坏了删掉容器，几十秒回到初始状态
::: notes
“在我电脑上能跑”是软件行业的老问题，Docker 就是为解决它而生的。
:::

## 四个概念
- **镜像**：只读的模具，如 `apache/hadoop:3.4.3`
- **容器**：用镜像做出来的运行实例，如 master、worker1
- **端口映射**：`9870:9870`，宿主机端口:容器端口
- **数据卷**：容器删了数据还在，如 HDFS 的数据
::: notes
口诀：镜像是模具，容器是产品；端口映射是窗口，数据卷是保险柜。注意 Docker 容器和第 4 章 YARN 的“容器”不是一回事。
:::

## 安装与国内镜像加速
| 系统 | 安装 |
|---|---|
| Windows 10/11 | Docker Desktop（启用 WSL 2） |
| macOS | Docker Desktop |
| Linux | Docker Engine + Compose 插件 |
::: notes
国内下载慢：配置 registry-mirrors 加速地址（以老师提供的为准），或老师 docker save 导出、学生 docker load -i 导入。Docker Desktop 内存不少于 6 GB。
:::

# 2.3 一条命令启动集群

## 随书集群
- **master**：NameNode、ResourceManager、JobHistoryServer、HttpFS
- **worker1、worker2**：DataNode、NodeManager
- 存数据的机器同时跑计算：移动计算
- 都是后台运行的**守护进程**
::: notes
NameNode、DataNode 第 3 章讲；ResourceManager、NodeManager 第 4 章讲。本章先跑起来。
:::

## 看懂 docker-compose.yml 的四个问题
- 用哪个**镜像**？`apache/hadoop:3.4.3`
- **主机名**叫什么？master、worker1、worker2
- 开了哪些**端口**？9870、8088、19888、14000
- 挂载了哪些**文件和数据卷**？conf、labs、master-data
::: notes
三个容器在同一个网络 bigdata_default 里，互相用主机名访问，例如 hdfs://master:8020。
:::

## 动画：集群地图
!sim cluster-map
- 点容器看进程、端口、数据卷
- 点端口看请求怎样转进容器
- 加 worker3、停 worker2
::: notes
提问：为什么浏览器打不开 worker2 的 9864 端口？（宿主机的 9864 已经映射给了 worker1）
:::

## 启动、停止和重置
```bash
docker compose up -d        # 启动
docker compose ps           # 看状态
docker compose logs master  # 看日志
docker compose exec master bash
docker compose down         # 删容器，数据保留
docker compose down -v      # 连数据一起清空
```
::: notes
第一次启动会格式化 NameNode，只做一次。容器一两秒就起来，守护进程要二三十秒才就绪。
:::

# 2.4 Hadoop 配置文件

## 四个配置文件
| 文件 | 管什么 | 关键配置 |
|---|---|---|
| core-site.xml | 全局 | HDFS 地址 hdfs://master:8020 |
| hdfs-site.xml | HDFS | 副本数 2、块大小 128 MB |
| yarn-site.xml | YARN | 每节点 2 GB、2 核 |
| mapred-site.xml | MapReduce | 任务各 512 MB |
::: notes
最常改的只有副本数和 YARN 内存。查配置项含义去官方文档搜名字。
:::

## 改了配置怎样生效
- 守护进程只在启动时读配置：要 `docker compose restart`
- 用 `hdfs getconf -confKey dfs.replication` 确认
- 坑：编辑器替换了文件，容器里还是旧的，重启即可
- 副本数只影响**新文件**，已有文件用 `-setrep`
::: notes
编者实测：sed -i 改完，容器里仍是 2；restart 后 getconf 显示 3。实验 2-3 验证“只影响新文件”。
:::

# 2.5 检查与排错

## 三层检查
- **进程**：`jps`，master 4 个、每个 worker 2 个
- **节点**：`dfsadmin -report`、`yarn node -list`
- **网页**：9870 看 HDFS，8088 看 YARN
- 一键：`bash check_cluster.sh`
::: notes
Live datanodes 应为 2，Total Nodes 应为 2，总资源 4 GB、4 vCores。
:::

## 9870 网页 Overview
![9870 Overview 页](img/hdfs_overview.png)
::: notes
重点看 Live Nodes 2、Dead Nodes 0、Under-Replicated Blocks 0。
:::

## 排错三步走
- **看状态**：`docker compose ps`
- **看日志**：`docker compose logs <容器名>`
- **对照排查表**：端口被占、Exited (137) 内存不够、镜像下载失败、UNHEALTHY 磁盘满
::: notes
端口被占：改 ports 冒号左边。内存不够：Docker Desktop 调到 6 GB 以上。实在不行 down -v 重来。
:::

## 三条上机路线
| 路线 | 适合 |
|---|---|
| 自己的电脑 | 内存 8 GB 以上，推荐 16 GB |
| 云主机 | 4 核 16 GB 按量付费，用完释放 |
| 学校实训平台 | 学校提供在线环境 |
::: notes
集群运行时约占 3～4 GB 内存。云主机的网页端口不要直接开放到公网。
:::

- 里面跑的还是 NameNode、DataNode……排错方法照样适用
