# 大数据技术处理技术

**课程名称：** 大数据技术处理技术

**授课对象：** 成人教育（开放教育）人工智能技术应用专业专科学生，多为在职学习者，线上自学为主

**学分学时：** 4 学分，72 学时（理论 60 学时，实验 12 学时）。其中线上理论 46 学时、线上实验 12 学时、线下理论 14 学时。第 3 学期开设，期末闭卷考试

**先修要求：** 学过“Python 程序设计”（会写函数、会用列表和字典、会用 pandas 读表）、“Linux 操作系统”（会用常用命令、会编辑文本文件、知道什么是进程和端口）和“数据库基础与应用”（会写 SELECT、GROUP BY、JOIN）。“机器学习”在同一学期开设，本课用到的机器学习知识都在书中留有速记，不要求先学。

**对应证书：** 人才培养方案没有给本课挂职业技能证书，书中不设“证书考点对照”页。

## 课程概述

一家电商平台每天产生上亿条点击、加购、下单记录，一座城市的交通卡口每秒都在上传车辆数据，一个大模型的训练语料动辄几十 TB。这些数据一台电脑存不下、算不完，必须把成百上千台普通服务器组织起来一起存、一起算。大数据技术就是做这件事的一整套方法和工具：Hadoop 把文件切成块分散存储在集群上，MapReduce 和 Spark 把计算任务拆开交给每台机器并行执行，Hive 和 Spark SQL 让人用熟悉的 SQL 查询海量数据，Kafka 和流计算让数据一产生就能被处理，MLlib 让机器学习跑在集群上。对人工智能技术应用专业的学生来说，大数据是“喂养”人工智能的上游：训练数据的采集、清洗、存储和加工，模型上线后的数据回流和监控，都离不开大数据平台。

本课程坚持“看得见、跑得通、用得上”的原则。每个分布式概念先用生活中的例子讲清楚它在解决什么问题，再用交互动画把“数据怎样在机器之间流动”画出来，最后在自己的电脑上用 Docker 搭起一个小集群，亲手把数据放进去、把任务跑起来。全书只用 Python 和 SQL 编程，不要求会 Java。

课程按一条数据的“旅程”组织：先认识大数据和它的技术生态，搭好实验集群；然后学习 Hadoop 的三大核心组件——分布式文件系统 HDFS、计算模型 MapReduce 和资源管理器 YARN，以及建在它们之上的数据仓库 Hive；接着进入 Spark，学习 RDD 编程、用 Spark 做数据清洗、用 DataFrame 与 Spark SQL 做数据分析；再学习用 Kafka 和 Structured Streaming 做实时处理、用 MLlib 做分布式机器学习；最后学习常见性能问题的排查、数据可视化和数据合规，并完成一个从原始数据到销售看板的综合项目。全书用一家虚构的电商平台“小象优选”作为贯穿案例，每章处理它数据旅程中的一段。

全书 12 章、36 个实验。实验分三种环境：只装 Python 和 Java 就能跑的 PySpark 本地模式；在自己电脑上用 Docker 启动的 Hadoop、Hive、Spark、Kafka、MySQL、Superset 小集群（建议内存 8 GB 以上）；以及按量付费的云主机或学校实训平台。实验数据全部由随书脚本按固定随机种子生成，规模可以从几万行调到上千万行，让学生亲眼看到“数据变大以后会发生什么”。

学完本课程，学生能够在一个小型 Hadoop/Spark 集群上完成一次完整的离线数据处理和一次简单的实时处理：把数据存进 HDFS、用 Hive 或 Spark SQL 清洗和统计、用 MLlib 建一个模型、把结果做成图表和看板，能读懂作业运行页面、找出慢在哪里，并在处理个人信息时做好脱敏和权限控制。

## 主要内容

本课程按“会用为主、原理够用”的原则组织内容：每章先讲“能做什么”，再讲“怎么做”，原理只讲到能看懂操作结果、出了问题知道往哪儿找。

| 章 | 内容 | 学完能做什么 |
|---|---|---|
| 1 | 大数据的概念与 5V 特征，单机与集群，大数据处理流程与组件地图，国产大数据平台与岗位 | 说清一个业务场景要用哪些大数据组件；用 PySpark 跑通第一个统计 |
| 2 | Linux 速记，Docker 的镜像、容器、端口、数据卷，用 Docker Compose 启动 1 主 2 从的 Hadoop 集群，常见故障排查 | 一条命令启动 Hadoop 集群，会检查、会排错 |
| 3 | HDFS 的 NameNode、DataNode、数据块与副本，常用命令，用 Python 读写 HDFS，小文件问题与对象存储 | 用命令和网页管理集群上的文件 |
| 4 | MapReduce 的 Map、Shuffle、Reduce，Combiner，用 Python 写 Hadoop Streaming 程序；YARN 的组成与作业查看 | 用 Python 写 MapReduce 程序统计日志，在 YARN 上查看作业 |
| 5 | 数据仓库与分层，Hive 的内部表、外部表、分区表，HiveQL 统计与窗口函数 | 用 HiveQL 建表、导入数据、做统计报表 |
| 6 | Spark 的 Driver、Executor 与 Job、Stage、Task，RDD 的转换与行动，Spark UI，Spark on YARN | 用 PySpark 读数据、做转换和统计，在 Spark UI 上看作业 |
| 7 | 缺失值、重复值、异常值、格式统一、日期处理、正则提取、多表合并 | 把一份脏数据清洗成可以分析的数据 |
| 8 | DataFrame 与 Spark SQL，Parquet，窗口函数，电商常用指标，RFM 用户分层，读写 Hive 与 MySQL | 用 DataFrame 和 SQL 完成多维分析和用户分层 |
| 9 | Kafka 的主题、分区、偏移量与消费者组，Structured Streaming，事件时间、窗口、水位线与检查点，Flink 简介 | 搭一个按分钟统计成交额的实时任务 |
| 10 | 机器学习速记，MLlib 的特征处理与 Pipeline，逻辑回归、随机森林、K-Means，评估、调参、保存与批量打分 | 用 Pipeline 在 Spark 上训练、评估、保存模型 |
| 11 | 用 Spark UI 定位问题；小文件、CSV、大表关联小表、数据倾斜、内存不够五类问题的现象、原因与改法 | 按排查表定位并解决 5 类常见性能问题 |
| 12 | 选图原则与误导性图表，pyecharts，Superset 数据看板，个人信息保护法、数据安全法、分类分级、脱敏与最小权限，综合项目 | 做出销售看板，完成一个从原始数据到看板的项目 |

## 不涉及的内容

- Linux 系统管理与 Shell 编程，归“Linux 操作系统”课程；本书只在第 2 章留一页速记
- SQL 基础语法与关系数据库设计，归“数据库基础与应用”课程
- 机器学习算法原理（逻辑回归、决策树、K-Means 等怎样工作），归同学期的“机器学习”课程；本书只讲在 Spark 上怎样跑
- 用 Java 或 Scala 开发 MapReduce 和 Spark 程序
- 偏底层和偏运维的内容：HDFS 的 FsImage、EditLog 与高可用，YARN 的调度器细节，Spark 的 Catalyst 优化器与内存管理，流处理的“精确一次”语义，生产集群的安全认证（Kerberos）与容量规划；这些只在“前沿视窗”中用一两句话带过
- HBase、ZooKeeper 的部署与编程，只在生态介绍中讲作用

## 学习目标

完成本课程后，学生能够：

### 记忆（Remember）

- 说出大数据的 5V 特征，以及数据量单位 KB、MB、GB、TB、PB 之间的换算关系
- 列举本书用到的大数据组件（HDFS、YARN、MapReduce、Hive、Spark、Kafka、Superset）及其作用
- 复述 HDFS 中 NameNode、DataNode 的职责，默认块大小和默认副本数
- 说出 Kafka 中主题、分区、偏移量、消费者组的含义
- 说出个人信息保护法、数据安全法与大数据项目有关的要点

### 理解（Understand）

- 用自己的话解释“分而治之”和“移动计算而不是移动数据”为什么能处理单机处理不了的数据
- 说明 MapReduce 一次作业中数据经过 Map、Shuffle、Reduce 的过程，以及 Shuffle 为什么最耗时
- 说明 Spark 为什么通常比 MapReduce 快，Job、Stage、Task 之间是什么关系
- 说明事件时间、处理时间和水位线的区别
- 解释列式存储、列裁剪和谓词下推怎样减少读取的数据量

### 应用（Apply）

- 使用 Docker Compose 启动一个 Hadoop/Spark 小集群，并通过网页检查各节点状态
- 使用 HDFS 命令和 Python 上传、下载、查看文件和数据块
- 使用 Python 编写 Hadoop Streaming 程序，完成日志统计
- 使用 HiveQL 建立分区表、加载数据并完成统计报表
- 使用 PySpark 的 RDD、DataFrame 和 Spark SQL 完成清洗、聚合、关联和排名
- 使用 Kafka 和 Structured Streaming 搭建一个按分钟统计成交额的实时任务
- 使用 MLlib 的 Pipeline 完成特征处理、模型训练、评估和保存
- 使用 pyecharts 和 Superset 把分析结果做成报告和看板，编写手机号、身份证号的脱敏代码

### 分析（Analyze）

- 根据数据规模、时效要求和查询方式，判断一个业务场景该用批处理还是流处理、Hive 还是 Spark
- 阅读 Spark UI，找出一个慢作业中耗时最多的阶段，通过任务耗时分布识别数据倾斜

### 评价（Evaluate）

- 判断一项优化（换 Parquet、广播、加盐、调整分区数）是否真的有效，并用实验数据说明
- 识别误导性图表；评估一个大数据项目在个人信息保护和数据安全方面的风险，提出脱敏和权限控制措施

### 创造（Create）

- 为一个业务场景设计数据处理流程图，标明每一步使用的组件
- 综合项目：以“小象优选”电商平台为例，完成从数据采集、脱敏、清洗统计、用户分群到可视化看板的全过程，并提交项目报告
