## 教学说明

**学习目标**

1. 能根据文件大小和块大小算出块数、根据副本数算出占用的硬盘空间（应用）；
2. 能解释 NameNode 和 DataNode 的分工，以及“坏一台机器数据还在”的原因（理解）；
3. 能判断在给定副本数和节点数下，坏几台机器会导致副本不足或数据丢失（分析）。

**画面与操作**

- 先选文件大小、块大小、副本数和 DataNode 台数，按“上传”。① 显示文件被切成的块，② 显示每台 DataNode 上存的块（同色是同一块的副本），③ 是 NameNode 的“账本”，和 `hdfs fsck -files -blocks -locations` 的输出对应。
- 点某台 DataNode 的“停掉”，再按“NameNode 检查一次”，补出来的新副本带黄色边框。点“启动”让机器回来，多余的副本会被删掉。

**数据来源**：默认的 702 MB 文件与随书 `labs/data/xiaoxiang_big/access.log` 一致。编者在随书集群上传它，`hdfs fsck` 显示 6 个块，前 5 块各 134217728 字节（128 MB），最后一块 64765908 字节（约 62 MB），副本数 2。停掉 worker3 后约 1.5 分钟被判定死亡，随后副本自动补齐（实验 3-2）。动画中的放置规则做了简化，不考虑机架。

**课堂用法建议**

1. 默认设置上传，请学生先算块数和占用空间，再按“上传”核对。
2. 副本数 2、3 台机器，停掉一台并检查：数据完整。再停掉第二台并检查：出现丢失的块。请学生总结“副本数为 N 时最多能同时坏几台”。
3. 副本数 3、DataNode 2 台，一上传就副本不足，对应实验 2-3 中把副本数改成 3 却只有 2 个节点的情况。
4. 把块大小改成 64 MB 和 256 MB，比较块数，引出“小文件多了 NameNode 记不过来”的问题。
