## 教学说明

**学习目标**

1. 能画出同一张表在行式存储和列式存储中的排列顺序（理解）；
2. 能说明列裁剪和谓词下推为什么能让 Parquet 少读数据（理解）；
3. 能根据查询的特点判断行式和列式各自适合的场景（评价）。

**画面与操作**

- 选择查询（只求一列的和、按省统计已完成订单、按金额过滤、按订单号查一行），切换“行式（CSV）”和“列式（Parquet）”。
- 列式存储把 8 行分成 2 个行组，每组内一列接一列存放，并记下 amount 和 order_id 的最小值、最大值；勾选“用最小值 / 最大值跳过行组”后，不可能满足条件的行组整组跳过。
- 蓝色格子是必须读出的数据，虚线格子是被跳过的数据，下方统计要读的格子数和占比。

**数据来源**：示意数据，8 笔订单为编者虚构。实验 11-1 用 300 万行订单实测：CSV 239.8 MB，Parquet 51.8 MB，按省统计销售额时 Parquet 只需读 3 列约 6.7 MB。

**课堂用法建议**

1. 先选第 1 个查询，在行式和列式之间切换，让学生说出两者读的格子数为什么不同。
2. 选第 3 个查询，取消、再勾选“用最小值 / 最大值跳过行组”，引出谓词下推，对照实验 11-1 执行计划中的 `PushedFilters`。
3. 选第 4 个查询，讨论：网站的订单详情页（按订单号查一行）应该用行式还是列式存储？
